## 完整方案

产品方案统一维护在 App 仓：[贷款完整改造方案](https://github.com/TNT-Likely/BeeCount/blob/a46b0391e6c8dfdc343d5673fdc0fa84ea844c91/docs/features/LOAN_ACCOUNTS_PLAN_ZH.md)。

方案覆盖本息拆分、还款计划、周期账单接续、付款与减本金关联、统计口径、实际账单核对、提前还款/利率变更、旧估值账户与同步恢复验收。它仍是讨论提案，恢复前需重新确认产品取舍，不能直接视为已批准的开发范围。

## 当前实现与缺口

- 已实现：贷款本金账户、同币种本金借还、旧余额接续、相关校验、Web 本金入口与 `loan-flow-v1` 同步保护。
- 利息只能另记普通支出，没有与一次还款统一关联。
- 未实现：本息分配、计划、周期支出联动减本金、计划与实际账单核对及完整计划变更。
- 当前测试记录只覆盖手动本金账户实现，不能作为完整房贷管理已通过验收的证据。

## 恢复时的检查顺序

1. 先核对实际月供记账流程，决定付款支出与消费支出的口径，并控制初始化及每期操作复杂度。
2. 复核旧贷款和既有周期账单接续规则，避免重复记支出或重复减少本金。
3. 确定本息/计划/付款业务对象及 App、Web、API/MCP、备份恢复的新契约；不能让旧端绕过关联还款保护。
4. 在最新 main 上重评现有差异，再实施并按 isolated-app-cloud-qa 做完整双端验收。
